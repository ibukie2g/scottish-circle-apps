# sports-day データ設計(下書き)

作成:2026-11-11　アプリ・運営画面・Claude(スプレッドシート連携)が、同じシートを読み書きするための約束。
仕様の全体は OneDrive の `Univ\スコサー\2026年度\合同運動会\Webアプリ仕様書.md`。

## 0. ファイルの分け方と個人情報の扱い
| スプレッドシート | 中身 | イベント後 |
|---|---|---|
| **名簿**(参加登録フォームの回答。既存) | 名前、性別、大学、学年、所属、出身地、学籍番号、参加、到着時間、同意。運営が「チーム」列を足して A〜D を書く。アプリ用に「参加者ID」列と「当日追加」「自己紹介」のシートを足す | 残す(サークルの名簿) |
| **アプリ用**(イベントごとに新しく作る) | 下の1〜12のシート。当日のデータ | **残す(イベントの記録)**。次のイベントでは新しいファイルを作る |

**個人情報はアプリ用ファイルに置かない**(2026-11-11 伊吹の方針)
- 名前・出身地・自己紹介など個人がわかる情報は、すべて**名簿ファイル**だけに置く。アプリ用ファイルには**参加者ID(P01など)だけ**を書く
- アプリは、名前が必要なとき(名前を選ぶ画面、クイズの判定、答え合わせ)に名簿ファイルを読み、メモリ上でIDと結びつける。アプリ用ファイルにはコピーしない
- 当日追加の人と自己紹介(スポーツ、ひとこと、あだ名)は、名簿ファイルの中の別シート「当日追加」「自己紹介」に書く(アプリが名簿ファイルに書き込むのはこの2シートだけ。フォームの回答シートは書き換えない)
- クイズで入力された名前そのものは、アプリ用ファイルに保存しない。判定の結果(正解と判定した人のID、正答率)だけを保存する。「惜しい答え」の入力だけは運営の確認のために一時的に保存し、確認が終わったら消す
- スプレッドシートのIDと運営パスワードは、Apps Scriptのスクリプト プロパティに保存する(コードに書かない)
- シート名・列名は日本語。1行目が見出し。Claudeが直接読み書きしても壊れないように、列の順番を変えない

## 1. 状態(1シート、キーと値)
| キー | 値の例 | 説明 |
|---|---|---|
| モード | 待ち/予想/クイズ/結果待ち/結果公開 | 参加者の画面を何にするか |
| 今の種目 | バスケ | 待ち画面に出す |
| 次の種目 | バド+ドッジ | 待ち画面に出す |
| 予想の試合ID | V-SF1 | モードが「予想」のとき、どの試合か |
| クイズ開始時刻 | 2026-11-24 21:30:00 | 制限時間の計算に使う |
| 更新時刻 | (自動) | |

アプリは状態を10秒だけキャッシュする。シートを直接書き換えても10秒以内に反映される。

## 2. 参加者(名前は持たない)
| 列 | 例 | 説明 |
|---|---|---|
| 参加者ID | P01 | 名簿ファイルの「参加者ID」列と同じ。名前は名簿ファイルで引く |
| チーム | A | 名簿の「チーム」列から読み込む。当日の変更もここ |
| 来場時刻 | | 端末で名前を選んだ時刻(=来ている人)。予想の「全員」とクイズの計算に使う |
| 当日追加 | TRUE/FALSE | 当日追加した人(名前は名簿ファイルの「当日追加」シート) |
| クイズに含める | TRUE/FALSE | 途中参加などで計算から外すとき FALSE |

## 3. 自己紹介 → 名簿ファイルの「自己紹介」シートに置く
| 参加者ID | やっていたスポーツ | ひとこと(20字) | あだ名(任意) | 更新時刻 |

## 4. 試合
| 列 | 例 | 説明 |
|---|---|---|
| 試合ID | B-R1-1 | 下の一覧 |
| 種目 | バスケ/バド/ドッジ/バレー | |
| 回 | 1ラウンド/準決勝①/3位決定戦/決勝 | |
| チーム1 / チーム2 | A / B | 決勝・3位決定戦は準決勝の確定で自動で入る |
| 点数1 / 点数2 | 12 / 8 | バスケは前半+後半(クイズ)の合計を入れる |
| 状態 | 予定/確定 | |
| 予想の状態 | なし/受付前/受付中/公開 | バレーだけ使う |
| 関連試合 | | ドッジの試合に、同時に行うバドの試合IDを書く |

最初から入れておく試合(16試合):
- バスケ:B-R1-1(A-B)、B-R1-2(C-D)、B-R2-1(A-C)、B-R2-2(B-D)、B-R3-1(A-D)、B-R3-2(B-C)
- バド:D-SF1(A-C)、D-SF2(B-D)、D-3RD、D-F
- ドッジ:G-1(B-D、関連 D-SF1)、G-2(A-C、関連 D-SF2)、G-3(関連 D-3RD)、G-4(関連 D-F)。チームはバドに出ていない2チーム
- バレー:V-SF1(A-B)、V-SF2(C-D)、V-3RD、V-F

## 5. 予想
| 試合ID | 参加者ID | チーム | 予想(勝つチーム) | 更新時刻 |
- 1人1試合1行。公開までは上書きOK

## 6. クイズ問題(クイズ開始時に自動で作る)
| 参加者ID | 出身地の対象者ID | 選択肢1〜4(都道府県名) | 正解 |
- 対象者は ID だけ。名前は画面に出すときに名簿から引く

## 7. クイズ回答
| 参加者ID | 書いた人数 | 正解と判定した人のID | 名前の正答率 | 出身地の回答 | 出身地の正誤 | 送信時刻 |
- 入力された名前そのものは保存しない

## 8. 惜しい答え
| 参加者ID | 入力 | 近い候補(参加者ID) | 判定(未/OK/NG) |
- 運営が OK にすると、クイズ回答の正答率を計算し直す
- 入力は個人情報なので、判定が終わったら「入力」の列を消す

## 9. お題カード
| お題番号 | お題 | チーム | そろった人数 | 答えた人数 |
- 点数は集計で計算(全員一致なら2点、それ以外は1.5 × そろった人数 ÷ 答えた人数)

## 10. アンケート(匿名)
| 送信時刻 | 楽しかったか(1〜5) | 普段話さない人と話せたか(1〜5) | また参加したいか | 自由記述 |
- 参加者IDは保存しない。二重送信は端末側で防ぐ

## 11. 設定(キーと値)
| キー | 初期値 |
|---|---|
| 順位点 | 10,7,4,2 |
| バレー勝ちボーナス | 3 |
| クイズ:名前の満点 / 出身地の満点 | 7 / 3 |
| お題カード:全員一致 / それ以外の係数 | 2 / 1.5 |
| 予想:1試合の満点 | 2 |
| クイズ:名前の制限時間(秒) / 出身地(秒) | 120 / 15 |

## 12. 集計(アプリが自動で書き込む。人とClaudeが読む用)
| チーム | バスケ順位点 | バド順位点 | ドッジ順位点 | バレー点(点数+ボーナス) | 運動の合計 | クイズ | お題カード | 予想 | 仲良しの合計 | 総合 | 運動だけの順位 | 総合順位 |
- 点数は小数第1位まで
- 試合の確定、お題カードの入力、クイズの判定のたびに書き直す
- 同点のとき:バスケは勝ち数 → 得失点差、ドッジは勝ち数が同じなら同順位
