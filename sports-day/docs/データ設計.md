# sports-day データ設計

作成:2026-11-11(2026-11-11 サーバー側の実装に合わせて更新)　アプリ・運営画面・Claude(スプレッドシート連携)が、同じシートを読み書きするための約束。
画面から呼ぶ関数は `docs/API.md`。
仕様の全体は OneDrive の `Univ\スコサー\2026年度\合同運動会\Webアプリ仕様書.md`。

## 0. ファイルの分け方と個人情報の扱い
| スプレッドシート | 中身 | イベント後 |
|---|---|---|
| **名簿**(参加登録フォームの回答。既存) | 名前、性別、大学、学年、所属、出身地、学籍番号、参加、到着時間、同意。運営が「チーム」列を足して A〜D を書く。アプリ用に「参加者ID」列と「当日追加」「自己紹介」のシートを足す | 残す(サークルの名簿) |
| **アプリ用**(イベントごとに新しく作る) | 下の1〜12のシート。当日のデータ | **残す(イベントの記録)**。次のイベントでは新しいファイルを作る |

**個人情報はアプリ用ファイルに置かない**(2026-11-11 伊吹の方針)
- 名前・出身地・自己紹介など個人がわかる情報は、すべて**名簿ファイル**だけに置く。アプリ用ファイルには**参加者ID(P01など)だけ**を書く
- アプリは、名前が必要なとき(名前を選ぶ画面、クイズの判定、答え合わせ)に名簿ファイルを読み、メモリ上でIDと結びつける。アプリ用ファイルにはコピーしない
- 当日追加の人と自己紹介(スポーツ、ひとこと、あだ名)は、名簿ファイルの中の別シート「当日追加」「自己紹介」に書く(アプリが名簿ファイルに書き込むのはこの2シートと、フォームの回答シートの「参加者ID」列の採番だけ。フォームの回答シートのほかの列は書き換えない)
- クイズで入力された名前そのものは、**どのスプレッドシートにも保存しない**(変更履歴に残るため)。判定の結果(正解と判定した人のID、正答率)だけを保存する。「惜しい答え」の入力だけは運営の確認のために **CacheService に6時間だけ**置き、判定したら消す
- スプレッドシートのIDと運営パスワードは、Apps Scriptのスクリプト プロパティに保存する(コードに書かない)
- シート名・列名は日本語。1行目が見出し。Claudeが直接読み書きしても壊れないように、列の順番を変えない

## 1. 状態(1シート、キーと値)
| キー | 値の例 | 説明 |
|---|---|---|
| モード | 待ち/予想/クイズ/結果待ち/結果公開 | 参加者の画面を何にするか |
| 今の種目 | バスケ | 待ち画面に出す |
| 次の種目 | バド+ドッジ | 待ち画面に出す |
| 予想の試合ID | V-SF1 | モードが「予想」のとき、どの試合か |
| クイズ開始時刻 | 2026-11-24 21:30:00 | 制限時間の計算に使う。全員この時刻を基準に進む(名前 = 開始〜+120秒、出身地 = その後15秒) |
| 予想の受付開始時刻 | 2026-11-24 20:40:00 | 運営が「予想の受付を開始」を押した時刻。運営画面に経過時間を出すのに使う(2026-11-13 追加) |
| 更新時刻 | (自動) | |

- モードが上の5つ以外のときは「待ち」とみなす
- モードを「クイズ」にするときは、運営画面の「クイズ開始」(adminStartQuiz)を使う(クイズ開始時刻と問題を作るため)。シートを直接「クイズ」にした場合は、クイズ開始時刻を手で入れること

アプリはシートの読み取りだけを10秒キャッシュし、状態・集計の派生キャッシュは持たない。シートを直接書き換えても10秒以内に反映される。

## 2. 参加者(名前は持たない)
| 列 | 例 | 説明 |
|---|---|---|
| 参加者ID | P01 | 名簿ファイルの「参加者ID」列と同じ。名前は名簿ファイルで引く |
| チーム | A | 名簿の「チーム」列から読み込む。当日の変更もここ |
| 来場時刻 | | 端末で名前を選んだ時刻(=来ている人)。予想の「全員」と、クイズの名前の対象(チームで来場している人)に使う。スマホがない人は運営が入れる |
| 当日追加 | TRUE/FALSE | 当日追加した人(名前は名簿ファイルの「当日追加」シート) |
| クイズに含める | TRUE/FALSE | 途中参加などで計算から外すとき FALSE(空欄は TRUE とみなす) |

- チームは名簿の「チーム」列から読み込む。2回目以降の読み込みでは、すでにいる人のチームは上書きしない(当日の変更を消さないため。上書きは運営画面のオプション)

## 3. 自己紹介 → 名簿ファイルの「自己紹介」シートに置く
| 参加者ID | やっていたスポーツ | ひとこと(20字) | あだ名(任意) | 写真のSNS掲載 | 更新時刻 |
- やっていたスポーツ:バスケ/バレー/バドミントン/その他/特になし
- 写真のSNS掲載:顔OK/顔を隠せばOK/載せない
- 保存するたびに下に1行足す(30人同時でも待たせないため、ロックなしの `appendRow`)。同じ人の行が複数あれば、いちばん下(最新)を使う。setup() が見出し付きで作る

## 3-2. 当日追加 → 名簿ファイルの「当日追加」シートに置く
| 参加者ID | フルネーム(漢字) | フルネーム(ひらがな) | チーム | 出身地(都道府県) | 追加時刻 |
- 運営画面の「当日追加」で書く。参加者IDはフォームの回答の人と同じ連番(P01〜)

## 4. 試合
| 列 | 例 | 説明 |
|---|---|---|
| 試合ID | B-R1-1 | 下の一覧 |
| 種目 | バスケ/バド/ドッジ/バレー | |
| 回 | 1ラウンド/準決勝①/3位決定戦/決勝 | |
| チーム1 / チーム2 | A / B | 決勝・3位決定戦は準決勝の確定で自動で入る |
| 点数1 / 点数2 | 12 / 8 | バスケは前半+後半(クイズ)の合計を入れる |
| 状態 | 予定/確定 | 「確定」の試合だけ集計に入る |
| 予想の状態 | なし/受付前/受付中/公開 | バレーだけ使う。「公開」= 締め切り(予想した2チームに人数の集計を見せ、変更不可)。受付中のまま点数を確定すると、自動で「公開」になる |
| 関連試合 | | ドッジの試合に、同時に行うバドの試合IDを書く |

最初から入れておく試合(18試合 = バスケ6+バド4+ドッジ4+バレー4):
- バスケ:B-R1-1(A-B)、B-R1-2(C-D)、B-R2-1(A-C)、B-R2-2(B-D)、B-R3-1(A-D)、B-R3-2(B-C)
- バド:D-SF1(A-C)、D-SF2(B-D)、D-3RD、D-F
- ドッジ:G-1(B-D、関連 D-SF1)、G-2(A-C、関連 D-SF2)、G-3(関連 D-3RD)、G-4(関連 D-F)。チームはバドに出ていない2チーム
- バレー:V-SF1(A-B)、V-SF2(C-D)、V-3RD、V-F
- 準決勝が2試合とも確定すると、決勝(勝者どうし)・3位決定戦(敗者どうし)・G-3/G-4 のチームが自動で入る。準決勝を直したときも入れ直す
- バド・バレーは引き分けで確定できない。バスケ・ドッジの引き分けは0.5勝として数える

## 5. 予想
| 試合ID | 参加者ID | チーム | 予想(勝つチーム) | 更新時刻 |
- 締め切るまでは何度でも送り直しOK。その人専用の行に上書きする(ロックなし)。同じ人・同じ試合の行が複数あれば、いちばん下(最新)の行を使う
- チームは予想したときのチーム。試合に出ている2チームの人は予想できない
- **締め切るまで、予想の中身(人数の内訳)はだれにも見せない**(2026-11-13)。全員がそろっても自動では公開しない。運営が締め切る(または点数を確定する)と、予想した2チームに人数だけの集計を見せる。試合が確定したら的中率(全体・チームごと)も見せる
- 素早く変えたときのために、端末が押した時刻を番号として送る。番号は CacheService の `predSeq:試合ID:参加者ID` に6時間置き、古い番号の送信は書かずに捨てる

### 5-2. 予想公開(2026-11-13 から使っていない)
| 試合ID | チーム |
- 「全員そろったら公開」をやめたので、アプリはこのシートに書かない。シートは残してある(消さなくてよい)

## 6. クイズ問題(名前の対象IDだけ保存)
| 参加者ID | 名前の対象者ID | 出身地の対象者ID | 選択肢1 | 選択肢2 | 選択肢3 | 選択肢4 | 正解 |
- 列順の互換性のため見出しは維持するが、出身地の対象者ID・選択肢・正解の列はすべて空欄にする。
- 名前の対象者IDは自分以外の来場している同チームのIDをカンマ区切り。来場者がいなければ同チーム全員。
- 出身地の問題(対象者ID・選択肢・正解)は CacheService の `origin:参加者ID` に6時間だけ保存する。
- キャッシュ消失時は別問題を自動生成せず NO_QUIZ を返す。運営が regenerate:true で未回答者の問題を作り直す。
- 既存シートの旧データは読み出しに使用しない。過去の変更履歴はコード更新では消去できない。

## 7. クイズ回答
| 参加者ID | 書いた人数 | 正解と判定した人のID | 名前の正答率 | 出身地の回答 | 出身地の正誤 | 送信時刻 |
- 入力された名前そのものは保存しない。名前の対象が0人なら正答率は空欄。
- 出身地の回答列は互換性のため残すが常に空欄。自分の選択肢と完全一致した入力だけ採点し、それ以外は不正解。
- 出身地についてシートに書くのは正誤だけ(問題なしは空欄)。答え合わせ用の有効な選択は `originResponse:参加者ID` に6時間だけ保存する。失効時は yourAnswer が空文字、問題自体の失効時は origin が null。
- 1人1行。再送しても最初の回答のまま。30人同時に送るのでロックは取らず `appendRow` で足し、同じ人の行が2つあれば最初の行を使う。送る直前に状態シートを読み直し、結果公開後は拒否する。

## 8. 惜しい答え
| 番号 | 参加者ID | 近い候補(参加者ID) | 判定 |
- 判定:未/OK/NG。番号は参加者IDから決める(P07 なら 701, 702 …。運営画面で OK/NG を押すときに使う)。ロックなしで足すので、同じ番号が二重になったら最初の行を使う
- **入力そのものはシートに書かない**。CacheService に `near:番号` で6時間だけ置き、運営画面はそこから読む。判定したらキャッシュから消す
- キャッシュが消えていても(入力が見られないだけで)判定・集計はできる。集計は「クイズ回答」の結果だけで行う
- 運営が OK にすると、クイズ回答の「正解と判定した人のID」に足して正答率を計算し直す。OK のあと NG にすると取り消す

## 9. お題カード
| お題番号 | お題 | チーム | そろった人数 | 答えた人数 |
- お題番号+チームで1行(上書き)
- 点数は集計で計算(全員一致なら2点、それ以外は1.5 × そろった人数 ÷ 答えた人数)。答えた人数が0なら0点

- お題番号は1〜3の整数だけ。集計時は範囲外を無視し、同じ番号・チームが重複した場合は先頭の1行だけ採用する。

## 10. アンケート(運営だけが見る)
| 送信時刻 | 楽しかったか(1〜5) | 普段話さない人と話せたか(1〜5) | また参加したいか | 自由記述 | 参加者ID |
- 2026-11-11 決定:匿名にはしない(運営が誰の回答かわかってよい)。名前は保存せず、参加者IDだけ。画面には「回答は運営だけが見ます」と出す
- 30人が同時に送っても待たせないように、参加者シートと同じ行番号の行に書く(送り直したら上書き)。名前を選んでいない端末からの回答は、ロックを取って下に足す
- 二重送信は端末側でも防ぐ

## 12. 集計(アプリが自動で書き込む。人とClaudeが読む用)
| チーム | バスケ順位点 | バド順位点 | ドッジ順位点 | バレー点(点数+ボーナス) | 運動の合計 | クイズ | お題カード | 予想 | 仲良しの合計 | 総合 | 運動だけの順位 | 総合順位 |
- 行は A〜D の4行。点数は小数第1位まで(内訳ごとに丸めて足す)
- 運営の操作(試合の確定・修正、お題カードの入力、惜しい答えの判定、予想の状態の変更、参加者の変更、設定の変更、結果公開、集計の取得)のたびに書き直す。**参加者のクイズ送信のたびには書き直さない**(30人同時の負荷を避けるため。運営画面で集計を開くと最新になる)
- 同点のとき:バスケは勝ち数 → 得失点差、ドッジは勝ち数が同じなら同順位。同順位のチームには、その順位の点を両方に与える(例:2位が2チームなら両方7点、次は4位)
- バスケ・ドッジの順位点は、その種目の全試合が確定してから入る。バドは決勝・3位決定戦が確定したところから入る。バレーは確定した試合の分だけ入る
- 回答者・予想者がいないチームは、その項目0点
