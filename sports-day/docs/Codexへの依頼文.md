■ 作るもの:運営画面(sports-day/src/ の運営画面用HTMLファイル)
・スマホ縦向きで操作する。画面の下にタブを5つ並べる
  1. 進行:今の種目・次の種目の切り替え、参加者の画面のモード(待ち/予想/クイズ/結果待ち/結果公開)の切り替え、クイズ開始、結果の公開
  2. 試合:18試合の一覧(種目ごと)。2チームの点数を入れて「確定」。確定後も直せる。決勝・3位決定戦は準決勝の確定で自動で埋まる。バレーの試合では、勝敗予想の受付開始・締め切り・公開
  3. 順位:運動の点数だけの順位と、仲良しポイント込みの順位、内訳。結果発表で読み上げるので、「仲良しポイントを足す前」→「足したあと」の順に見られるようにする。数字は大きく
  4. クイズ:回答した人数、惜しい答えの一覧(OK/NGを押す)、お題カードの入力(お題1〜3ごとに、チームのそろった人数/答えた人数。答えた人数は最初から来場人数を入れておく)
  5. 名簿:当日来た人の追加(名前・ひらがな・チーム・出身地)、チームの変更、クイズの計算に含めるかの切り替え、自己紹介を入力した人の数
・最初に運営パスワードを入力する画面(API.md の方法に従う)
・押し間違いが困る操作(クイズ開始、結果の公開、予想の公開)は、確認を1回はさむ
・保存中は「保存中…」、成功したら短く「保存しました」と表示。失敗したらわかる言葉で理由を出す

■ 守ること
・AGENTS.md のとおり、参加者画面のファイルやサーバー側(.gs)のファイルは編集しない。サーバーの関数が足りないときは、勝手に作らず、足りない関数と理由を最後の報告に書く
・clasp push と git push はしない。git commit はしてよい
・外部の重いライブラリは使わない。見た目は AGENTS.md の方針(クリーム色の背景、白い角丸のカード、チームカラー 赤A・青B・黄C・緑D)

■ 最後に報告してほしいこと(日本語で短く)
・作ったファイル
・API.md にない関数が必要だったか
・自分で判断して決めたこと
