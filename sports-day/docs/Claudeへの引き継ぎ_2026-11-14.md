## 追加したバスケ画面

伊吹さんから「前半と後半で内容が違い、合計を手計算するのに時間がかかる。前半の点数と、後半の何問目にどのチームが答えたかを入力して自動計算したい」と追加依頼があった。**ラウンドごとに4チームをまとめる形式は本人が選択済み。**

使い方:

1. 運営画面 → 試合 → バスケ → ラウンド1〜3。
2. 前半の4チームの得点を入力（0点も明示して入力）。
3. 後半は使う問題を「+ かんたん / + ふつう / + むずかしい」から追加する。
4. 各問題で、コートごとに正解したチームを順にタップ。先に正解・あとから正解の点が自動で入る。不正解では押さず、正解なしは空のまま。
5. 「内訳を途中保存」は記録だけを保存し、試合の点数は変えない。別端末からも読み直せる。
6. 「合計を2試合に反映して確定」→合計を確認→「2試合を確定」。確定済みの点数も置き換える。訂正した場合も同じ手順で再確定する。

配点は既存の企画概要.mdの決定を使用:

| 難しさ | 先に正解 | あとから正解 |
|---|---|---|
| かんたん | 2点 | 1点 |
| ふつう | 3点 | 2点 |
| むずかしい | 5点 | 3点 |

例:前半A6/B4/C0/D7点、難問1問でB→A、C→Dの順に正解 → A9/B9/C5/D10点。実際のブラウザでも入力・途中保存・2試合への反映を確認した。

主なファイル:

- `src/core_basket.js`:純粋な計算・入力検証。同じ関数を `doGet` が運営HTMLにも埋め込む。
- `src/api_basket.js`:取得・途中保存・確定。古い版の保存はCONFLICTで拒否。確定時はサーバーで再計算。
- `src/admin_script.html` / `admin_style.html` / `admin.html`:入力・確認・保存・合計表示。
- `src/setup.js` / `store.js`:新設シート「バスケ内訳」。リセット対象にも追加。
- `tests/core_basket.test.js` / `basket_api.test.js`:配点・不正入力・保存・確定・訂正・競合・リセット。
- `tools/admin_preview/server.js`:共有計算関数の埋め込みと、390pxの `/phone` 確認画面。

シートとAPIの詳細はデータ設計.mdの「14. バスケ内訳」とAPI.mdの `adminGetBasketballRound` / `adminSaveBasketballRound` に記載。既存の列順は変更していない。

## 仕様書にない部分でCodexが決めたこと

- 自動正解0人の控えを `-` で表す。旧形式の空欄との区別のため。旧形式を読む互換処理は維持する。
- 予想は同じ選択でも送信する。直前の送信が時間切れの場合、サーバーでは別の選択に変わっている可能性があるため。
- 出身地クイズは「Cで同じ県の複数人を使う」より「3問をそろえる」を優先し、必要なら別の県のCかBで埋める。対象不足の場合だけ作れる数にする。
- 負荷テストの1通信の時間切れを30秒にする。GASの実際の性能を示す基準ではなく、テストを終了・集計できるようにするため。
- バスケの問題は初期0問、使った分だけ追加し、上限は1ラウンド30問。番号はラウンド内の第1問から。問題文・不正解の試行は保存しない。
- バスケの正解を外すと、もう片方に残った正解が「先に正解」になる。正解順を逆にしたい場合は両方外して正しい順に押す。
- バスケの途中保存は手動。画面の更新・ブラウザ終了を越えて残すには途中保存する。未保存で一覧へ戻る・別ラウンドへ切り替える・保存済みを読み直す際は確認を出す。
- バスケの内訳は「合計の直接入力」と独立。直接入力で合計を直しても内訳は逆算しない。再確定時は確認のうえ内訳の合計で上書きする。
