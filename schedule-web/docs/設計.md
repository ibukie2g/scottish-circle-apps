**安全の基本方針**
1. すべての表に RLS をかける。**参加者は表を直接読み書きしない**。参加者の操作は、合言葉と本人の確認をしてから必要なものだけを返す **サーバー側の関数(RPC、security definer)** だけで行う
2. 幹事・管理者は、RLS で許された行だけを直接読む(運営画面)
3. 秘密の鍵(service_role)は画面にもリポジトリにも入れない。使うのは、伊吹のパソコンで動かす「Aからの引っ越し」スクリプトだけ(`.env` に置き、`.gitignore` 済みにする)

## 2. 表(Postgres)

すべて `id uuid default gen_random_uuid()`、`created_at timestamptz default now()`。

### staff(管理者・幹事)
| 列 | 型 | 説明 |
|---|---|---|
| user_id | uuid PK → auth.users | Google でログインした人 |
| role | text check in ('admin','organizer') | |
| display_name | text | 運営画面に出す名前 |

### groups
| 列 | 型 | 説明 |
|---|---|---|
| id | uuid PK | |
| name | text | |
| kind | text check in ('circle','group','once') | circle=サークル(名簿を使う)/group/once=1回きり |
| token | text unique | リンクの合言葉(ランダム20文字以上。推測できない) |
| owner_id | uuid → auth.users | 作った人(管理者か幹事) |
| mascot | boolean default true | つなぼるを出すか |
| archived | boolean default false | しまう |

### members(名前はここだけ)
| 列 | 型 | 説明 |
|---|---|---|
| id | uuid PK | |
| group_id | uuid → groups | |
| user_id | uuid null → auth.users | 名前を選んだ人(匿名ログインのID)。だれも選んでいなければ null |
| name | text | フルネーム/表示名 |
| kana | text | サークルだけ |
| grade | text | サークルだけ |
| gender | text | サークルだけ(絞り込み用) |
| roster_key | text | 運動会の名簿の参加者ID(P01…)。引っ越しと重複防止用 |
| active | boolean default true | 抜けた人は false |
| unique(group_id, name) where active | | 同じグループに同じ名前は1人 |

### events
| 列 | 型 | 説明 |
|---|---|---|
| id | uuid PK | |
| group_id | uuid → groups | |
| name, description, place, cost, url | text | |
| status | text check in ('poll','time','rsvp','done') | 日程調整中/時間調整中/出欠確認中/終了(time は「10.」の2段階) |
| visibility | text check in ('names','counts','hidden') | 名前も見せる/人数だけ/見せない |
| deadline | date null | 日本時間のその日の終わりまで |
| decided_candidate_id | uuid null → candidates | |
| created_by | uuid → auth.users | |

### event_organizers(イベント単位で任された幹事)
| event_id | user_id | PK(event_id, user_id) |

### candidates
| id | event_id | date date | time text('19:00' か '') | memo text | stage text check in ('date','time') default 'date' |

### answers(○△×。1候補日×1人 = 1行)
| event_id | member_id | candidate_id | mark text check in ('o','t','x') | updated_at | PK(member_id, candidate_id) |

### responses(イベントごとの「ひとこと」と出欠)
| event_id | member_id | comment text | attendance text null check in ('go','partial','no') | arrive_at text | att_comment text | updated_at | PK(event_id, member_id) |

### wanted(来てほしい人)
| event_id | member_id | PK(event_id, member_id) |

### 表どうしの食い違いを防ぐ制約(見直しで追加)
- `candidates unique(id, event_id)`・`members unique(id, group_id)`・`events unique(id, group_id)`
- answers / responses / wanted は `group_id` も持ち、`(member_id, group_id) → members(id, group_id)`・`(event_id, group_id) → events(id, group_id)`・answers は `(candidate_id, event_id) → candidates(id, event_id)` の複合外部キー。ほかのグループの人やほかのイベントの候補日では行を作れない
- `events (decided_candidate_id, id) → candidates(id, event_id) on delete set null (decided_candidate_id)`
- **作ったあと変えられない列**:events.group_id・candidates.event_id・members.group_id(トリガーで旧値と比べて止める)。groups.owner_id を変えられるのは管理者だけ
- members:正規化した名前の列(A案の normalizeName と同じ)に **部分ユニークインデックス** `(group_id, name_norm) where active`、`unique(group_id, roster_key)`、`unique(group_id, user_id)`(1人1つの名前)
- `members.user_id → auth.users on delete set null`(匿名ユーザーを定期的に消しても、名前と答えは残る)
- `event_organizers.user_id → staff(user_id) on delete cascade`(幹事を外すと、任されたイベントも自動で外れる)
- グループ・イベントの**物理的な削除は管理者だけ**。幹事は「しまう」(archived)だけ

※最初の案にあった group_access 表はやめた(RPC が毎回合言葉を確かめるので不要。自分のグループ一覧は端末の控えで足りる)

## 3. RLS(だれがどの行を読めるか)

補助の関数(security definer、`set search_path = ''`、表は `public.xxx` と完全な名前で書く。**`private` スキーマに置き、画面から呼べないようにする**):
- `is_staff()`:匿名でない(JWT の is_anonymous が false)かつ staff にいる。**ほかの補助関数はすべて最初にこれを確かめる**(幹事を外せば、owner_id が残っていても何もできなくなる)
- `is_admin()`:is_staff() かつ role = 'admin'
- `can_manage_group(g)`:is_admin() または (is_staff() かつ groups.owner_id = auth.uid())
- `can_manage_event(e)`:can_manage_group(イベントのグループ) または (is_staff() かつ event_organizers に自分がいる)
- 任された幹事に名前を見せる範囲:**members の直接の select は can_manage_group だけ**。任された幹事には、そのイベントの結果に必要な名前だけを、運営用の RPC(`staff_event_results(event_id)`)で返す(学年・男女・ふりがなまでは渡さない)

| 表 | 読む(select) | 書く(insert/update/delete) |
|---|---|---|
| staff | is_admin()、または自分の行 | is_admin() |
| groups | can_manage_group(id) または そのグループのイベントを任されている | insert:is_staff() かつ owner_id = auth.uid()/update・delete:can_manage_group(id) |
| members | can_manage_group(group_id)(任された幹事は RPC 経由のみ) | can_manage_group(group_id) |
| events | can_manage_event(id) | insert:can_manage_group(group_id)/update・delete:can_manage_event(id)(削除は can_manage_group のみ) |
| event_organizers | can_manage_group(イベントのグループ) または 自分の行 | can_manage_group(イベントのグループ) |
| candidates / wanted | can_manage_event(event_id) | can_manage_event(event_id) |
| answers / responses | can_manage_event(event_id) | can_manage_event(event_id)(運営が代わりに入れる) |

- **参加者(匿名)には、どの表の select も許さない**。参加者が見るものはすべて下の RPC から
- `anon` ロール(ログインしていない状態)には何も許さない。匿名ログインした人は `authenticated` ロールなので、is_staff() の中で is_anonymous を確かめて、staff の操作を許さない
- 関数は作っただけで anon にも実行権限が付くので、すべて `revoke execute ... from public, anon` → 参加者用 RPC だけ `grant execute ... to authenticated`

## 4. 参加者の RPC(security definer。すべて最初に本人と合言葉を確かめる)

| 関数 | 入力 | すること・返すもの |
|---|---|---|
| `open_group(token)` | 合言葉 | 合言葉が正しく、しまわれていなければ group_access に記録。グループの名前・種類・つなぼる、自分のメンバー(members.user_id = auth.uid())、イベント一覧(自分が答えたか、締め切り、決まった日) |
| `list_members(token)` | | 名前を選ぶ画面用:id・name・kana・grade・**選ばれているか**。サークル以外は name だけ |
| `claim_member(token, member_id)` | | その名前を自分にする(user_id = auth.uid())。**ほかの人がすでに選んでいる名前の扱いは「8. 決めること」** |
| `join_group(token, name, kana?, grade?, gender?)` | | 一覧にいない人が加わる。同じ名前がいれば止める |
| `get_event(token, event_id)` | | 候補日・自分の答え・結果。結果は visibility どおり(names なら名前、counts なら人数だけ、hidden なら null)。**ひとこと(comment)は返さない**(運営だけ) |
| `submit_answers(token, event_id, answers, comment)` | | 締め切り前・日程調整中だけ。自分のメンバーとしてだけ書ける |
| `submit_attendance(token, event_id, status, arrive_at, comment)` | | 出欠確認中だけ |

- 自分のメンバー = `members.user_id = auth.uid()` の行。member_id を画面から受け取らない(なりすまし防止)
- 合言葉は毎回確かめる。しまわれた・合言葉が変わったグループは開けない
- **event_id は必ず「合言葉で引いたグループのイベントか」を確かめる**(`e.id = p_event and e.group_id = g.id`)。answers の candidate_id がそのイベントのものかも確かめる
- claim は1文で行う:`update public.members set user_id = auth.uid() where id = $1 and group_id = $g and active and user_id is null`(同時に押されても1人だけが取れる)
- 入力の上限:答えの記号は o/t/x だけ、候補日は1イベント60まで、ひとこと100文字、名前20文字。join_group は1人1グループ1名前まで
- 締め切りの判定は `(now() at time zone 'Asia/Tokyo')::date <= deadline`(current_date は UTC なので使わない)
- 結果の見せ方(visibility)は、日程調整の結果だけでなく**出欠の一覧と来てほしい人にも効かせる**。「ひとこと」(comment・att_comment)はどちらも参加者には返さない
- 合言葉は `gen_random_bytes(16)` 以上を base64url にしたもの(総当たりはまず無理)
- 匿名ログインの乱用対策:Supabase の匿名サインインの回数制限(IPごと)を確認して設定する。必要なら Turnstile(CAPTCHA)を入れる。使われなくなった匿名ユーザーは定期的に消す(名前と答えは残る)

## 5. 画面

A案と同じ流れ・同じ見た目。

- **名前の取り違えに気づけるように(11/27 伊吹)**:参加者の画面の上に「**◯◯ さん**として答えています」を大きく出し、すぐ横に「ちがう」ボタン(押すと名前を選び直す)。送るボタンの上にも「◯◯ さんとして送ります」。名前を選んだ直後は「◯◯ さん、ようこそ!」を大きめに出す

## 9. 見直しで直したこと(11/27、別のエージェントによる安全面のレビュー)
- 任された幹事が events.group_id を書きかえて、ほかのグループの名前を読める穴 → 作ったあと変えられない列にした
- event_organizers に staff 以外を入れられる/外した幹事が権限を持ち続ける → 補助関数の最初で is_staff() を確かめ、staff への外部キーにした
- 合言葉と event_id の組み合わせを確かめていない → RPC で必ず確かめる
- answers などがほかのグループの人・ほかのイベントの候補日でも入る → 複合外部キー
- 引っ越し直後に他人の名前を先に取られる → claim を1文にし、名前の扱いを決める(下の8-1)
- そのほか:search_path、関数の実行権限、合言葉の作り方、締め切りのタイムゾーン、部分ユニークインデックス、任された幹事に見せる名前の範囲、visibility の範囲、消すのは管理者だけ、鍵の扱い
- やりすぎと言われて外したもの:group_access 表、テスト専用のプロジェクト(ローカルで足りる)、管理者の JSON 書き出し(Supabase の画面の CSV 書き出しで代わりになる)

   - 案ウ:最初に名前を選んだとき、4けたの「合言葉(PIN)」を自分で決める。別のスマホで同じ名前を選ぶときは、そのPINを入れれば選び直せる。忘れたら幹事が解除

## 10. A案で 11/27 に足した機能(Bにも入れる)

A案(schedule)の @6〜@10 で入れて、伊吹が本番で確かめたもの。B案でも同じ動きにする。

### 10-1. 日にちを決めてから時間を聞く(2段階)
- 日程調整中の時刻は「目安」と表示する(「日にちが決まってから、時間をあらためて聞くこともあります」)
- 運営が「この日に決める」を押すと、**そのまま出欠確認に進む**か**時間も聞く**(時間の候補を入れる)かを選ぶ
- 時間も聞く:`events.status = 'time'`、`decided_candidate_id` = 決めた日の候補。時間の候補は `candidates.stage = 'time'`、`date` = 決めた日
- 参加者は**同じリンクのまま**。「12/19(土)に決まりました!何時からがいい?」と時間の候補に ○△× をつける。締め切り(日程のためのもの)には関係なく答えられる。カレンダーに追加は出さない
- `submit_answers` は poll(締め切りまで)と time のときだけ。**いまの段階の候補の答えだけ書きかえ、ほかの段階の答えとひとことは残す**
- `get_event` の候補・自分の答え・結果は、いまの段階の分。前の段階の結果は `date_stage` として「日程調整のときの回答」に出す
- 運営が「この時間に決める」:status = 'rsvp'、`decided_candidate_id` = 時間の候補。時間の答えから ○→行く/×→行かない を仮に入れる
- 戻すのは1段ずつ:出欠確認中(時間まで決めた)→ 時間調整中 → 日程調整中。日程調整中に戻すときは時間の候補を消す(answers は candidate への外部キーの on delete cascade で一緒に消える)
- 時間調整中は、時間の候補だけを足す・消す。決まった日の候補は消せない

### 10-2. メンバーを削除・戻す(二重登録の対策)
- 運営のグループの画面で、メンバーごとに「答え ◯件」(答えたイベントの数)と「削除」。どちらを消すか決める手がかり
- 削除 = `members.active = false`(行は消さない)。答えは残るが、集計・名前を選ぶ画面・一覧に出なくなる。下の「削除したメンバー」から**戻せる**(答えも戻る)
- **削除するとき `user_id` を null にする**(`unique(group_id, user_id)` があるので、残すとその人が別の名前を選べない)。戻した名前はだれも選んでいない状態になる
- 戻すとき、同じ名前(name_norm)の人がいれば部分ユニークインデックスで止まる → 「同じ名前の人がいます」と出す
- サークルの名簿から足す処理は、削除した人も「もういる」とみなして、戻ってこないようにする

### 10-3. 名前の空白ちがいを同じとみなす
- `name_norm` は **空白(全角も)をすべて取ったもの**にする(「山田太郎」「山田 太郎」「山田　太郎」は同じ)。join_group で止める

### 10-4. 「いちばん多い日」は同点ならすべてに
- 並べ方:○が多い順 → △が多い順 → 日付・時刻が早い順
- 印は、○も△も1位と同じ数の候補**すべて**につける(○が0なら印なし)

### 10-5. ほかのグループのイベントもまとめて見る
- A案はスマホが覚えている「グループのリンク+そこで選んだ自分」で結んだ。B案は **`my_events()`**:`members.user_id = auth.uid() and active` の行があるグループ(しまわれていないもの)の、終わっていないイベントを返す。合言葉はいらない(その名前を選んだ時点で、そのグループのリンクを持っていたことになる)
- **名前では結ばない**(別の名前で入っていても見える/同じ名前の別人の予定は混ざらない/リンクを開いていないグループは出ない)
- 参加者の画面:グループの一覧の下に「ほかのグループ」(グループ名・「◯◯ さんとして」・まだ/答えた)、イベントの画面の下に「ほかのグループにも、まだ答えていないのが◯こあるよ」
- Google でログインしてつないでおけば(linkIdentity)、スマホを替えても続けて見られる(あったら嬉しい程度)

### 10-6. 名前を選ぶ画面
- 「この名前で参加する」の下に「または」の区切りと、大きなボタン「前にこのグループに入ったことがある(自分の名前を一覧から選ぶ)」
- `open_group` がメンバーの人数を返し、名前の一覧を待たずにボタンを先に出す(画面がずれて出ないように)
